# T08 인증 구현 설명서 — 내 소개 페이지에 패스키 달기

> **초안입니다.** 항목은 매뉴얼의 T08 완성 기준(사용한 도구와 선택 이유, 바꾼 부분, 접근 차단을 확인한 기록, AI와 내가 맡은 일, 아직 해결하지 못한 점)에 맞췄습니다. 현재 과제 화면의 기준과 다르면 화면 기준으로 고칩니다.
> 비밀번호·토큰·키는 적지 않습니다. 시험에는 예시 데이터만 씁니다.

- 결과물 URL: https://hyejinlim.vercel.app (공개 소개 페이지) · https://hyejinlim.vercel.app/private.html (패스키로 잠긴 영역)
- 소스 URL: (제출 직전 commit으로 채움)

## 1. 무엇을 만들었나

- **공개 영역:** 1번 과제의 소개 페이지(`index.html`)는 그대로 누구나 볼 수 있다. 메뉴에 `🔒 Private` 링크만 하나 더했다.
- **비공개 영역:** `private.html`. 패스키로 들어가야 하며, 그 안의 메모는 **서버가 로그인한 본인에게만** 보낸다. 페이지 파일 자체에는 비공개 내용이 들어 있지 않다.
- **패스키 기능:** 가입(첫 패스키 만들기), 로그인, 로그아웃, 패스키 추가 등록, 패스키 삭제(마지막 하나는 삭제 불가).

## 2. 사용한 도구와 선택 이유

| 도구 | 역할 | 고른 이유 |
| --- | --- | --- |
| WebAuthn(패스키) | 비밀번호 없는 로그인 | 서버에는 공개키만 남아, 서버가 털려도 비밀번호처럼 재사용될 비밀이 없다. 피싱 사이트에서는 브라우저가 서명을 거부한다(도메인 묶임) |
| `@simplewebauthn/server` 14.1.0 | 서버에서 등록·로그인 응답 검증 | 챌린지·출처·도메인·서명·카운터 검사를 직접 구현하지 않고 검증된 라이브러리에 맡김 |
| `@simplewebauthn/browser` 14.0.0 | 브라우저에서 패스키 창 띄우기 | 위 서버 라이브러리와 짝을 이루는 JSON 형식 |
| Vercel 서버 함수 (`api/`) | 인증·비공개 자료 API | 1번 페이지가 이미 Vercel에 있어 같은 주소에서 함께 동작 |
| Supabase(PostgreSQL) | 공개키·세션·메모 저장 | 6·7번에서 쓰던 프로젝트. `t08_*` 표는 브라우저 역할에 권한이 없고 서버만 접근 |

## 3. 바꾼 부분

| 파일 | 바꾼 것 |
| --- | --- |
| `index.html` | 메뉴에 `🔒 Private` 링크 한 줄 추가. 나머지 공개 내용은 그대로 |
| `private.html`, `private.js` | 비공개 영역 화면: 패스키 가입·로그인·로그아웃, 패스키 목록·추가·삭제, 비공개 메모 |
| `api/passkey.js` | 등록 옵션·검증, 로그인 옵션·검증, 로그아웃, 내 정보, 패스키 삭제 |
| `api/private.js` | 비공개 메모 읽기·쓰기·삭제 (로그인한 본인 것만) |
| `lib/http.js`, `lib/session.js`, `lib/db.js` | 쿠키·출처 검사, 세션(토큰은 쿠키, 해시만 DB), 저장소 |
| `supabase/t08-schema.sql` | `t08_users·passkeys·challenges·sessions·notes` 표, RLS 켜고 브라우저 역할 권한 회수 |
| `test/passkey.test.js` | 가상 패스키(실제 P-256 키와 서명)로 서버 흐름 전체를 시험 |

**지킨 규칙**
- 챌린지는 5분 동안 한 번만 쓸 수 있다(꺼내면서 지운다).
- 세션 쿠키는 `HttpOnly; SameSite=Strict; Secure`, 7일 뒤 만료. DB에는 토큰의 SHA-256 해시만 있다.
- 상태를 바꾸는 요청(POST·DELETE)은 우리 페이지 출처(Origin)에서 온 것만 받는다.
- 비공개 자료와 패스키 삭제는 항상 `세션의 user_id`로 걸러서 처리한다. 다른 사람 것을 지정해도 "없음"으로 응답한다.

## 4. 접근 차단을 확인한 기록

### 4-1. 자동 시험 (`npm test`, 2026-11-23)

실제 브라우저 대신 가상 패스키를 코드로 만들어(P-256 키 생성, 실제 서명) 서버 함수를 그대로 호출했다. 저장소는 메모리를 써서 실제 DB를 건드리지 않았다. **8개 모두 통과.**

| # | 시험 | 결과 |
| --- | --- | --- |
| 1 | 가입 → 내 정보 → 로그아웃 → 패스키로 다시 로그인 | 가입 200, 내 정보 200, 로그아웃 뒤 내 정보 **401**, 다시 로그인 200 |
| 2 | 패스키 추가 등록·삭제 | 두 번째 패스키 추가 200(기존 패스키는 제외 목록에 들어감), 두 번째 기기로 로그인 200, 첫 패스키 삭제 200, 마지막 패스키 삭제 **409**, 지운 패스키로 로그인 **401** |
| 3 | 다른 계정 차단 | bob이 alice 메모 목록 조회 → 빈 목록, alice 메모 삭제 → **404**(alice 메모는 그대로), alice 패스키 삭제 → **404** |
| 4 | 로그인 없이 | 비공개 메모 읽기·쓰기 **401**, 내 정보 **401** |
| 5 | 가짜 세션 쿠키 | **401** |
| 6 | 다른 사이트에서 보낸 요청 | **403** `bad_origin` |
| 7 | 다른 출처에서 서명한 응답 / 변조된 서명 / 이미 쓴 챌린지 재사용 | **401** / **401** / **400** `no_challenge` |
| 8 | 아이디 규칙 위반 / 중복 아이디 | **400** / **409** |

### 4-2. 배포 주소에서 확인 — 로그인하지 않은 요청 (2026-11-23)

`https://hyejinlim.vercel.app` 에 로그인하지 않은 상태로 HTTP 요청을 보냈다(curl). 실제 Supabase에 연결된 운영 배포다.

| # | 요청 | 응답 코드 | 응답 본문 (일부) | 판정 |
| --- | --- | --- | --- | --- |
| 1 | `GET /` | **200** | `<title>임혜진 \| AI 의약바이오 포트폴리오` | 공개 페이지는 누구나 열림 |
| 2 | `GET /private.html` | **200** | `<title>나만 보는 공간 …` (화면 틀만, 비공개 내용 없음) | 화면은 열리되 자료는 없음 |
| 3 | `GET /api/private` | **401** | `{"code":"unauthenticated","message":"로그인이 필요합니다."}` | 거절 |
| 4 | `GET /api/passkey?action=me` | **401** | `{"code":"unauthenticated",…}` | 거절 |
| 5 | `POST /api/private` `{"body":"x"}` | **401** | `{"code":"unauthenticated",…}` | 거절 |
| 6 | `GET /api/private` + 지어낸 세션 쿠키 | **401** | `{"code":"unauthenticated",…}` | 거절 |
| 7 | `POST /api/passkey?action=login-options` (Origin: 다른 사이트) | **403** | `{"code":"bad_origin","message":"허용되지 않은 출처에서 온 요청입니다."}` | 거절 |

| 10 | Supabase REST `t08_users·passkeys·sessions·notes` 직접 읽기 (공개 키) | **401** | `{"code":"42501",…}` (권한 없음) | 거절 |

## 6. 아직 해결하지 못한 점

- 누구나 아이디를 정해 계정을 만들 수 있다. 계정마다 자기 자료만 보이므로 내 메모는 안전하지만, "가입 자체를 나만 하게" 막지는 않았다.
- 모든 패스키를 잃으면 계정을 되찾을 방법(복구 코드 등)이 없다. 그래서 패스키를 두 개 이상 두도록 안내한다.
- 요청 횟수 제한(rate limit)이 없다.
- 실제 기기(지문·얼굴·화면 잠금)로 하는 확인은 배포 뒤에 해야 한다. 자동 시험은 가상 패스키로 했다.
- 6·7번과 같은 Supabase 프로젝트를 쓴다. `t08_*` 표는 브라우저 역할에 권한이 없지만, 서버 비밀 키가 새면 모든 표가 위험해진다. 키는 Vercel 환경변수에만 둔다.
